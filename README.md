# Abastible API Smoke Automation Framework
> Smoke API Automation Framework built with Postman, Newman and GitHub Actions.

Proyecto de automatización de pruebas Smoke para las APIs de Abastible utilizando Postman, Newman y GitHub Actions.

---

## Objetivo

Validar el funcionamiento de los servicios críticos de la API de Abastible mediante una colección Smoke que permita detectar rápidamente problemas funcionales antes de ejecutar pruebas de mayor alcance.

Actualmente el proyecto permite:

- Ejecutar pruebas Smoke de forma local.
- Ejecutar pruebas automáticamente mediante GitHub Actions.
- Generar ambientes dinámicamente utilizando variables de entorno.
- Mantener las credenciales fuera del repositorio.
- Generar reportes HTML de cada ejecución.

---

## Características

- Automatización de APIs con Postman.
- Ejecución mediante Newman.
- Reportes HTML con Newman HTML Extra Reporter.
- Generación dinámica de ambientes.
- Ejecución local mediante Bash.
- Integración continua con GitHub Actions.
- Gestión segura de credenciales mediante GitHub Secrets.

## Instalación

Clonar el repositorio:

```bash
git clone https://github.com/javi017/abastible-api-smoke.git
```

Ingresar al proyecto:

```bash
cd abastible-api-smoke
```

Instalar dependencias:

```bash
npm install
```

---

## Variables de entorno

El proyecto utiliza un archivo template ubicado en:

```text
environments/smoke/abastible-smoke-qa.example.postman_environment.json
```

Antes de ejecutar las pruebas se genera automáticamente:

```text
environments/smoke/abastible-smoke-qa.local.postman_environment.json
```

Las siguientes variables son inyectadas desde variables de entorno o GitHub Secrets:

| Variable |
|----------|
| API_BASE_URL |
| API_USERNAME |
| API_PASSWORD |
| API_DEVICE_ID |
| APP_VERSION |

---

## Ejecución local

Ejecutar el Smoke:

```bash
npm run smoke
```

El proceso realizará automáticamente:

1. Generación del ambiente local.
2. Ejecución de la colección Smoke.
3. Generación del reporte HTML.

---

## Reportes

Los reportes son almacenados en:

```text
reports/
```

Cada ejecución genera un archivo HTML con timestamp para facilitar el historial de ejecuciones.

---

## Integración Continua

El proyecto incorpora un workflow de GitHub Actions que permite ejecutar las pruebas:

- Manualmente (`workflow_dispatch`)
- Automáticamente en cada `push` a la rama `main`

## Flujo Smoke actual

Actualmente la colección automatiza el siguiente flujo funcional:

1. Login
2. Obtener Usuario
3. Obtener Customer ID
4. Obtener Detalle del Customer

Este flujo continuará creciendo para cubrir el proceso completo de creación de pedidos.
